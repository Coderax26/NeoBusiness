# Phase P2 — Business Decisions and Requirements Closure

## Objective

Remove ambiguity before frontend and production implementation. Every decision that changes calculations, permissions, workflow state, integrations, or UI must be recorded and reflected in code contracts and tests.

## Decision closure process

For each item:

1. Prepare a one-page decision brief with current behavior, options, recommendation, financial/operational impact, and affected modules.
2. Obtain owner/accountant/production confirmation.
3. Record status, decision text, date, and approver in `docs/OPEN_DECISIONS.md`.
4. Update affected blueprint and roadmap sections.
5. Update configuration defaults or database constraints.
6. Add acceptance tests and UI acceptance notes.
7. Add migration only when schema changes are required.

## Required decisions

### Finance and compliance

- OD-004: e-invoicing/IRN applicability and activation path.
- OD-005: e-way bill generated by NeoBus or accounting tool.
- OD-018: Tally Prime, Zoho Books, or another accounting target.
- OD-017: FIFO versus customer-specified invoice allocation.
- OD-023 operational procedure: opening-balance import ownership and sign-off.

### Operations and permissions

- OD-002: owner escalation value threshold for delivery disputes.
- OD-007: multi-site coordinator access model.
- OD-016: handover verification role.
- OD-015: whether custody includes UPI/bank transfers.
- OD-019 operational configuration: delegate caps and emergency escalation contacts.

### Procurement

- OD-009: supplier-specific versus item-wide price-spike baseline.
- OD-010: backup supplier tolerance.
- OD-011: freight/handling allocation into landed cost.
- Supplier bill approval and payment authorization policy.

### Production

- OD-012: yield variance basis.
- OD-013: make-to-order versus make-to-stock.
- Production stage tracking and parallel-batch capacity.

### Field workflows

- OD-006: OTP delivery channel.
- OD-008: driver/factory language set.
- OD-014: OTP ePOD requirement.
- Driver sales/van-sales policy.

### Dashboard semantics

- OD-020: definition of “today’s sales”.
- OD-021: expected dashboard refresh interval.
- Margin visibility by role.

## Contract updates required after decisions

- Permission matrix and role navigation.
- `business_rule_config` seed values.
- Event payloads and exception types.
- API DTO validation and response fields.
- Invoice, challan, ePOD, cash custody, and accounting export schemas.
- Frontend mock contracts and acceptance scenarios.

## Exit criteria

- No AWAITING decision remains for MVP scope.
- Every resolved decision has a code/test/documentation impact check.
- Owner-facing workflows and financial behavior are unambiguous.
